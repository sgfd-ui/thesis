# 机制1：基于历史验证的增量初始负载规划代码流程说明

## 1. 模块职责

代码层将本机制实现为执行前控制模块，负责读取历史控制状态、判定可复用范围、扫描残余分片、合成稳定统计贡献，并把历史计划种子和残余识别范围传递给第 6 章模块。

该模块不执行 join，不缓存 join 输出，也不直接复用上一轮物理任务计划。它只产生控制面结果：

```text
HistoryReuseResult {
  reuse_mode: FULL_REUSE | PARTIAL_REUSE | REBUILD
  K_reuse
  K_check
  Omega_residual
  plan_seed
  validation_summary
  resource_context
}
```

## 2. 输入状态

当前轮输入由版本化分片目录描述：

```text
ShardMeta {
  relation_id
  partition_id
  version
  snapshot_id
  row_count
  query_signature
  summary_pointer
}
```

历史状态按分片保存：

```text
ShardStats {
  meta
  candidate_summary
  exact_count_map
  sketch
  valid_until
}
```

查询级历史状态保存：

```text
HistoryControlState {
  structural_signature
  shard_version_vector
  H_R
  H_S
  state_combination_map
  work_estimate
  strategy_template
  parameter_rules
  execution_feedback
  confidence
}
```

## 3. 执行流程

整体入口流程如下：

```text
build_structural_signature(query)
  -> lookup HistoryControlState
  -> compare shard version vectors
  -> split stable shards and residual shards
  -> validate reusable historical keys
  -> scan residual shards if needed
  -> query stable contribution for new/boundary candidates
  -> decide FULL_REUSE / PARTIAL_REUSE / REBUILD
  -> emit HistoryReuseResult
```

结构签名不匹配、历史状态缺失或分片版本无法验证时，直接返回 `REBUILD`。分片版本稳定时，代码复用分片摘要和精确候选计数；残余分片必须重新扫描连接键列，不能只检查旧候选键。

## 4. 稳定贡献与残余贡献

对每个关系 $X\in\{R,S\}$，代码先构造：

```text
stable_shards_X
residual_shards_X
```

残余分片扫描输出：

```text
ResidualStats {
  residual_candidates
  residual_exact_counts
  residual_summary
}
```

对候选键 `k`，稳定贡献按优先级获取：

```text
if k in ExactMap of stable shards:
    use exact stable count
else if stable shard has key index:
    batch lookup count(k)
else:
    use Sketch estimate with error bound
```

最终输出频率可以是精确值，也可以是区间：

```text
plan_freq_lower = stable_lower + residual_exact
plan_freq_upper = stable_upper + residual_exact
```

若区间跨越热点阈值或 top-k 边界，键进入 `K_check`，交给第 6 章做边界确认。

## 5. 复用模式判定

`FULL_REUSE` 条件：

```text
structural_signature_match
all required shards stable
historical summaries valid
no unresolved boundary keys
new_hotspot_risk low
```

输出：

```text
Omega_residual = empty
K_check = empty
plan_seed = historical strategy templates
```

`PARTIAL_REUSE` 条件：

```text
signature match
some shards stable
some shards residual or uncertain
stable contribution query available
partial cost < rebuild cost
```

输出：

```text
K_reuse = verified stable historical keys
K_check = boundary or uncertain keys
Omega_residual = residual shard ranges
```

`REBUILD` 条件：

```text
signature mismatch
no matching history
version vector unavailable
summary incompatible
boundary lookup too expensive
residual ratio too high
```

输出：

```text
K_reuse = empty
Omega_residual = full current input
```

## 6. 成本触发回退

进入 `PARTIAL_REUSE` 前估计：

```text
C_partial =
  metadata_check
  + scan(residual_shards)
  + merge_summaries
  + query_stable_contribution(candidates)
  + boundary_validation

C_rebuild =
  scan(current_input)
  + full_candidate_detection
```

只有当 `C_partial < C_rebuild` 时才执行部分复用。若边界键过多、稳定分片回查接近全量读取、残余范围接近完整输入，则直接返回 `REBUILD`。

## 7. 输出给第 6 章

代码模块不生成完整初始计划，只输出：

```text
HistoryReuseResult {
  reuse_mode
  K_reuse
  K_check
  Omega_residual
  plan_seed: strategy_template + valid_scope
  validation_summary
  resource_context
}
```

第 6 章模块负责读取该结果，完成残余范围的双侧负载识别、边界回查和完整初始负载计划合成。
